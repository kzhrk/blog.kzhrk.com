今年の夏から、AI に4コマ漫画の連載をさせている。  
『アナーキストのアナちゃん、レイシストのレイちゃん』という作品で、[X（@ana_and_ra）](https://x.com/ana_and_ra)で公開している。脚本づくりから画像生成、検品、X への投稿まで、制作のすべてを Claude Code との会話だけで行っている。

この記事では、AI に漫画の連載を任せるために作った仕組みと、運用して得られた知見をまとめる。

## 作品について

思想が正反対の女子大学生2人がシェアハウスで暮らす日常4コマである。あらゆる制度を疑うアナーキストのアナと、無自覚に偏見を口にするレイの会話を通して、日常に染み込んだ思想をブラックユーモアとして描いている。

![第13話『推し活』](/images/2026-08-19-claude-code-yonkoma/1.jpeg)

画像は Nano Banana（Gemini の画像生成モデル）によるもので、AI 生成であることはアカウントの bio と `#AI漫画` タグで開示している。

## 制作パイプライン

制作は次の流れで進む。人間（自分）がやるのは、Claude Code とチャットで脚本を練ることと、最終的な採用判断だけである。

1. チャットで脚本を練り、Markdown 形式で保存する
2. 生成前セルフレビュー（後述する失敗パターンのチェック）
3. CLI から Nano Banana Pro に投げて4コマ1枚を生成する
4. 検品（絵柄チェックとセリフチェック）
5. 軽微な文字の瑕疵は再生成せず、画像編集で修正する
6. 採用が決まったらコマごとに分割し、X API で投稿する

それぞれ小さな Node.js / Python スクリプトになっていて、Claude Code が状況に応じて呼び分ける。最初は Web UI も作ったが、結局チャットで完結するほうが速く、早々に廃止した。

## いちばんの敵は画風ドリフト

運用してみて最大の敵は、生成のたびに画風が揺れることだった。同じプロンプトに参照画像を3枚添えても、時々まったく別の画風（ハイライトの強いキラキラした目、セル塗り、暖色に寄った画面）が出てくる。

厄介なのは、**セリフが完璧なテイクほど採用したくなる**ことである。実際に序盤は「セリフが全部正確だから」という理由で別画風のテイクを採用してしまう事故を2回起こした。今は「絵柄チェックとセリフチェックは独立していて、両方合格しないと採用しない」というルールを明文化している。

![別画風になった不採用テイク](/images/2026-08-19-claude-code-yonkoma/2.jpeg)

これは不採用にしたテイクで、セリフは全問正解だが、線が太く画面全体が暖色に寄っている。

絵柄の主観判定には限界があるので、客観的な検査も入れている。過去の採用作はページ外周の余白が RGB (248, 248, 248) 前後のニュートラルな白なのに対し、画風が暖色にドリフトしたテイクは余白がクリーム色に濁る。そこで余白のピクセルを数値で見る。

```bash
python3 -c "from PIL import Image; print(Image.open('take.jpeg').convert('RGB').getpixel((10,10)))"
```

R/G/B の差が 5 を超えていたら、他がどれだけ良くても機械的に不採用にする。「見た目の違和感」を数値のしきい値に変換できたのは大きかった。

## 文字化けのパターンは決まっている

日本語のセリフの文字化けは Nano Banana Pro でもそれなりに起きる。ただ、運用しているとパターンがはっきりしてくる。

- 1つの吹き出しが25文字を超えると化けやすい
- 同じ音の繰り返しに弱い（「いい大学」は5回連続で化けた）
- セリフに相手の名前が入ると、吹き出しのしっぽがその名前の人物側に付く
- 漫画は右から読むので、最初に話すキャラクターを画面右側に置かないとしっぽの誤爆が増える

対策はどれも生成側ではなく**脚本側**で行う。化けやすいセリフは言い換え、名前入りのセリフのコマは話者の単独ショットにする。生成のガチャを回して当たりを待つより、脚本を直すほうが確実で安い。

## 再生成するより編集で直す

Nano Banana は既存画像に指示を与える編集もできる。絵柄が合格でセリフの瑕疵が1〜2箇所だけのテイクは、捨てずに編集で直す。編集は他のコマに影響しないので、全面再生成のガチャよりはるかに安上がりである。

編集の指示にも知見が要る。たとえば修正後の文字列を『』で囲って指示すると、その括弧ごと画像に描かれてしまう。縦書きの吹き出しの重複文字を消すときは「縦書きで2列ある。左側の列の先頭にある カタカナ3文字 グッズ を消す」のように、列と位置まで特定すると一発で通る。文字以外でも、季節と矛盾して描かれた電気ヒーターを背景から消す、といった修正も編集で通った。

## 失敗はすべて Markdown に書いて AI に読ませる

この運用でいちばん効いているのは、技術ではなく仕組みの話である。

失敗するたびに、その教訓をリポジトリ内の `docs/production-notes.md` に追記している。採用基準、文字化けのパターン、編集指示のコツ、過去にやらかした誤採用の事例まで、すべてこのファイルにある。そして Claude Code には「制作の前に必ずこのファイルを読む」というルールを課している。

AI エージェントの記憶はセッションが変わると消える。だからこそ、失敗を人間の記憶ではなくリポジトリのドキュメントに変換しておくと、次のセッションの AI が同じ失敗を繰り返さなくなる。連載当初は1話採用までに最大18テイク引いたこともあったが、この蓄積が回り始めてからは2〜3テイクで済むようになった。

## X への投稿も API で自動化した

投稿は X API（OAuth 1.0a + `twitter-api-v2`）で行っている。2026年2月から X API はクレジット課金制になっており、無料枠を前提にした古い情報が多いので注意が必要である。

画像アップロードは罠が多く、v1.1 の `media/upload` は 402、v2 のチャンク式アップロードは 503 が返ってきて、最終的に通ったのは v2 のシンプルアップロードだった。

```js
const res = await client.v2.post(
  "media/upload",
  { media: buffer, media_type: "image/jpeg", media_category: "tweet_image" },
  { forceBodyMode: "form-data" },
);
```

これで「第N話を投稿して」とチャットで頼むと、本文の作成から画像4枚の添付、投稿までが完了するようになった。

## コスト感

Nano Banana Pro の生成コストは1枚あたり $0.13〜0.24 程度。テイク数は初期は2〜18枚とばらついていたが、セルフレビューと編集修正を導入してからは、おおむね2〜3テイク+編集1〜2回に収まっている。1話あたりのコストは缶コーヒー1〜2本分といったところである。

## まとめ

AI に連載を任せるといっても、実態は「生成ボタンを押すと漫画が出てくる」ような話ではない。画風の検品基準を作り、文字化けのパターンを蓄積し、失敗をドキュメントに変換してエージェントに読ませる。やっていることは、新人アシスタントの教育に近い。
